## Advanced mode usage

Choose **Advanced — requires native renderer** under the Studio edit assistant's planning mode. The API equivalent is `planner: "advanced"` on the existing plan request. A native worker is required before provider calls; simple mode remains available without it. The configured model is unchanged.

The response includes `planning.intent`, selected tools and their purpose, completed validation stages, and combined usage across the three calls. Existing approval applies canonical operations one at a time. Nothing is committed by planning. Still-frame automatic corrections are disabled for advanced plans until a compatible critic is implemented; users must review playback manually.

## Acceptance completed for the planner slice

- Missing worker is rejected before generation.
- Unavailable/unselected tools and out-of-scope side effects are rejected.
- Locked items remain unchanged and reference media cannot be inserted into output.
- The execution schema contains only selected canonical operations.
- Three provider stages produce a proposal that passes timeline and render-graph validation without mutating the source.
- The Studio service validates the transaction and checks the original revision before returning the proposal.

These are automated boundary tests with a mocked provider and capability snapshot. They are not native render or reference-fidelity benchmarks.
